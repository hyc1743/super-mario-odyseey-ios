# 仓库里有哪些与游戏有关的东西、哪些没有

参考项目有一份同样的说明（`docs/DERIVED.md`），它的口径是：**仓库里不含也不分发任何游戏内容**，
只记录「为了让移植成立必须知道的事实」。本文件把同样的口径落到本项目当前的实际状态上。

## 不在仓库里的

- 游戏程序（`main` / `sdk` / `subsdk0` / `rtld` 的任何一段代码）
- 美术、音频、过场动画
- 游戏文本（物品名、台词、界面文字等任何语言的字符串表）与数据表
- 着色器本体（`ShaderData/*.szs` 与其中 `*.sharc` 里的 Maxwell 程序），以及由它们翻译出来的 MSL 源码与 metallib
- 存档

这些全部在你自己的机器上、用你自己的游戏文件生成。发布导出时，参考项目会用一个工具拿真实游戏文件
逐字节搜索整棵树，命中就阻断导出；本仓库沿用同样的做法（见 `.github/workflows/build-shell-ipa.yml`
里 `shell_build.sh` 末尾的那段自我检查：壳里一旦出现游戏内容文件名就不再出包）。

## 在仓库里的

这些是**关于游戏的事实记录**，不是游戏内容。没有它们，就算你有自己的游戏文件也做不出能跑的包。

| 位置 | 是什么 | 为什么必须在仓库里 |
|---|---|---|
| `smo/tools/patch_nso.py` 里的改写规则（`CUTS` / `OBS`） | 每条规则读作「原指令字 → 新指令字」，原指令字用于核对版本与位置 | 改写器就是干这个的；**当前 SMO 的这两张表是空的**（还没登记任何剪口） |
| `smo/tools/*.py` | 解包、侦察、改写的工具本身 | 这些是本项目的代码，不含游戏内容 |
| `smo/ios/**` | App 壳的源码与出包脚本 | 同上；图标是脚本画的中性图形，不是游戏图标 |
| `STATUS.md` 里的量测数字 | 模块大小、构建号、导入条数、目录结构等 | 记录事实，用于复现与核对 |

## 以后可能会加进来的（同样不是游戏内容）

按参考项目的清单，随着移植推进还会加：

- 改写规则的**位置与理由**（每条都带原字节断言）
- 宿主 HLE 清单（哪些 `nn::` 函数被接管、理由）
- 着色器的**标识**（例如控制段的 sha256）与接口描述表 —— 不含着色器代码
- NVN 函数名表与调度点

每一项都会在本文件里逐项说明，口径与上面一致：**记录事实，不搬运内容。**
