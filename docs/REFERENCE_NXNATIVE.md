# nxnative 参考记录

核对日期：2026-10-17。参考项目：[seedds/nxnative](https://github.com/seedds/nxnative)。这里只记录对本项目有用的架构与测试经验，不复制游戏数据或项目实现。

## 触屏输入

nxnative 将触屏布局与实体控制器状态分开处理：提供两种可切换布局，记住用户选择，并在检测到实体控制器时隐藏触屏按钮。这个设计强调触屏必须是可操作的完整输入路径，也要避免盖住实体控制器用户的画面。

本项目已经提供双摇杆和 16 个触屏按键，并把输入送入 HID 状态；首次游戏画面出现时显示。当前还没有实体控制器自动检测或布局切换。后续若加入 GameController 支持，应在实体控制器连接/断开时切换覆盖层，并让选择后的布局持久化。

## 音频生命周期

nxnative 的已知问题记录提到，应用切后台再回来后，特定游戏可能暂时没有声音。这提醒我们把“播放中切后台、恢复后继续播放”作为独立验收场景，不能只验证音频单元成功启动。本项目已有 RemoteIO 中断和前后台处理；还需要真机确认恢复后 `AUDIO_SPEAKER played` 与混音计数继续增长，并实际听到声音。

## 性能与卡顿诊断

nxnative 说明首次进入新场景时的短暂卡顿可能来自着色器编译，并称编译结果会留到下次启动复用；它也用 `Documents/env.txt` 暴露无需重打包即可调整的运行参数。本项目把着色器源归档在包内以避免运行时翻译缺失的着色器，但这不等于已经有持久化的 GPU pipeline 缓存。当前提供 60/30 帧切换，并记录 CPU、帧率、内存和温控信息。后续若增加可配置项，应只开放经过验证的用户参数，不让配置覆盖 ABI、资源映射等内部约束。

nxnative 也说明其 CPU 与 Horizon 服务行为参考了 d2r-mobile、Ryujinx 和 Atmosphère。这里的借鉴方式是对照接口边界与回归方法；游戏资源、二进制实现和未经验证的参数不会从参考项目直接移植。
